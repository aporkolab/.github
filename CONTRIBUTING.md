# Contributing

Small fixes, useful bug reports, and well-explained changes are welcome. Follow the repository's own setup instructions and contribution guide where it has them.

## Report a problem

Check for an existing issue, then describe what you did, what happened, and what you expected. A small reproduction is more useful than a large log dump. Include versions or screenshots when they help, and remove credentials and personal data.

## Send a change

1. Fork the repository and make a branch for the change.
2. Keep the change focused. For a large feature or a change in direction, open an issue first so we can agree on the problem.
3. Run the relevant checks documented by the project. Add or update tests when they help demonstrate a behavior change; a typo fix does not need a new test suite.
4. Open a pull request explaining the problem, your solution, and what you checked. Say plainly if a check could not be run.

Follow the code around your change. There is no account-wide requirement for a particular commit-message format or development tool.

AI-assisted contributions are welcome. Read the result, verify it, and be ready to explain the decisions. Include relevant assumptions and limitations in the PR, regardless of which tools you used.

Keep discussion specific and respectful. Critique the change, help reproduce the problem, and leave room for a better solution.
